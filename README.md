# Бронирование переговорной

Минимальное приложение на React + TypeScript + Bun, на основе `bun-fsd-template`.
Одна комната, рабочий день 09:00–18:00. API эмулируется MSW в браузере, включая production-сборку.

## Запуск

Нужен Bun >= 1.3.

```sh
bun install --frozen-lockfile
bun run dev
```

Открыть [localhost:3000](http://localhost:3000). Worker уже находится в `public`, отдельный backend и переменные окружения не нужны.

В dev-режиме внизу страницы автоматически открывается локальный **XState Inspector**. В нём можно выбрать `daySchedule` или `meetingEditor`, посмотреть текущее состояние, context и последние 40 событий. Map отображается как объект по id, минутные слоты — как массив. Панель можно свернуть.

Официальный `@statelyai/inspect` установлен в devDependencies и подключён к корневой машине и её акторам. Кнопка **«Открыть Stately Inspector»** запускает официальный веб-инспектор в отдельной вкладке по клику; при блокировке нужно разрешить всплывающие окна. SDK сохраняет последние события до открытия окна и передаёт context и события в эту вкладку. API-сервис заменяется текстовой меткой, Map преобразуется в объект. В production-сборке оба инспектора и их обработчик inspection исключаются.

```sh
bun run build
bun run preview
```

Production preview: [localhost:4173](http://localhost:4173). Сборка копирует `mockServiceWorker.js` в dist. При статическом размещении этот файл нужно отдавать как JavaScript, остальные клиентские маршруты — через SPA fallback.

## Что работает

- Выбор даты, список встреч дня, создание, отдельный редактор и удаление с подтверждением.
- Ограничения рабочего дня, 30–120 минут, минутная точность и запрет прошлого времени. Начавшиеся встречи доступны только для просмотра.
- Проверка пересечений через 1440 минутных слотов, с разрешённым касанием границ и исключением собственной встречи при изменении.
- Оптимистическое создание/изменение/удаление, подтверждение ответа сервера и откат при ошибке.
- Обработка 409: новое расписание загружается, черновик не теряется. Ошибка повторного GET допускает отдельный повтор.
- После успешной записи и ошибки обновления встреча остаётся подтверждённой; повторяется GET, а не запись.
- Пустое состояние, загрузка, ошибки, блокировка повторных операций, адаптивная форма и клавиатурное подтверждение удаления.

По умолчанию выбран сегодняшний день, в 12:00–13:00 есть демонстрационная встреча. Если рабочий день закончился, выбрать будущую дату. Часовой пояс — локальный для браузера; API получает `YYYY-MM-DD` и `HH:mm` без UTC-преобразования выбранной даты.

Данные живут в памяти вкладки и сбрасываются при перезагрузке. Постоянного хранения, авторизации и синхронизации вкладок нет.

## Как проверить конфликт

1. Выбрать будущий свободный интервал.
2. Раскрыть «Проверить серверный конфликт» и нажать «Смоделировать конфликт».
3. Создать встречу.

Mock API добавит реальную конкурентную встречу и вернёт 409. Она появится в расписании, а введённые поля останутся в форме. Демонстрационный переключатель одноразовый и применяется к созданию; ошибки PATCH и сохранение редактора также проверяются тестами.

## Архитектура

- `entities/meeting` — встреча, DTO, маппинг и HTTP-сервис.
- `entities/day-schedule` — неизменяемые снимки дня, каталог встреч, проекция слотов, бизнес-правила и сервис расписания. Разрешён импорт day-schedule → meeting через публичный API.
- `features/meeting-editor` — отдельная машина XState v5, исходная встреча, черновик и форма. Она не изменяет расписание напрямую.
- `pages/home/model` — родительская машина: подтверждённый/оптимистический снимки, запросы через invoke/fromPromise, commit/rollback. Дочерний редактор живёт на корневом уровне и сохраняется при обновлении дня.
- `app/mocks` — MSW handlers и in-memory store с повторной серверной валидацией.
- `shared/api` — HTTP-клиент, типизированные ошибки и DI. Сервисы заменяемы без изменения UI; QueryStore шаблона не владеет бронированиями.

Guards используют чистые проверки; преобразования контекста выделены в функции. События имеют имена вида `meeting.save.requested`. При смене даты XState отбрасывает результаты устаревшего запроса. GET не прерывается транспортом при StrictMode-перезапуске актора; его устаревший результат игнорируется машиной.

Контракт: GET `/api/bookings?date=…`, POST `/api/bookings`, PATCH/DELETE `/api/bookings/:id`. Ошибки: 400 — валидация, 404 — отсутствующая встреча, 409 — пересечение. DELETE возвращает 204 без тела.

## Проверки

Перед первым запуском браузерных тестов:

```sh
bunx playwright install chromium
```

```sh
bun run check
bun run build
bun run test:e2e
bun run test:ct
```

`check` запускает TypeScript, oxlint, oxfmt и unit-тесты из src. E2E и CT выполняются отдельно. E2E использует настоящий browser MSW, фиксированные часы и изолированные вкладки; проверяет CRUD, 409, ошибки сохранения/обновления, прошлую дату и мобильную ширину.

Проверено локально: 44 unit-теста, 11 E2E и 2 CT; production preview — CRUD, worker и 409 без ошибок JavaScript. Это не проверка публичного deployment. Интеграция Stately SDK проверяется через тестовый receiver с протоколом подключения; доступность внешнего веб-инспектора не является условием CI.

Дополнительная обсуждавшаяся симуляция находится в docs и не используется как код приложения:

```sh
bun test ./docs/day-schedule.logic.test.js
bun build ./docs/day-schedule.machine.js --target=browser --external=xstate --outfile=./docs/day-schedule.simulator.js
```
