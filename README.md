# Бронирование переговорной

Приложение на React, TypeScript и Bun для одной переговорной с рабочим днём 09:00–18:00. Mock HTTP API работает через MSW в браузере, включая production-сборку. Отдельный backend и переменные окружения не нужны.

## Запуск

Нужен Bun >= 1.3; текущие проверки выполнены на Bun 1.4.4.

```sh
bun install --frozen-lockfile
bun run dev
```

Открыть [localhost:3000](http://localhost:3000). Для production preview:

```sh
bun run build
bun run preview
```

Preview доступен на [localhost:4173](http://localhost:4173). При статическом размещении нужны SPA fallback и раздача `mockServiceWorker.js` как JavaScript; сборка копирует worker в `dist`.

### Vercel

В корне добавлен [vercel.json](vercel.json): установка через `bun install --frozen-lockfile`, сборка `bun run build`, публикация `dist`. Root Directory проекта в Vercel должен указывать на корень этого репозитория.

Сначала раздаются существующие файлы, включая JS/CSS и `mockServiceWorker.js`; остальные адреса направляются на `index.html`, чтобы `/display` открывался напрямую. Конфигурация использует [параметры Vercel](https://vercel.com/docs/project-configuration/vercel-json). После загрузки изменений запустите новое развёртывание; его результат нужно проверить на конечном адресе.

## Возможности

- `/` — управление встречами: вертикальная сетка, выбор даты, создание, редактирование и удаление с подтверждением. Дата и черновики сохраняются при переходе между страницами без перезагрузки.
- `/display` — экран у двери: сегодняшний день на всю высоту планшета, без форм, действий и инспектора. Обновление каждые 30 секунд и при возвращении в окно; смена даты в полночь. При ошибке остаются последние данные и кнопка повтора.
- Длительность встречи 30–120 минут, ввод с точностью до минуты. Пересечения запрещены, касание границ разрешено; редактируемая встреча не конфликтует с собой. Начавшиеся и прошедшие встречи доступны для просмотра.
- Оптимистические изменения с подтверждением или откатом. При 409 обновляется расписание и сохраняется черновик. После успешной записи и неудачного обновления повторяется только GET.
- Часовые и четвертьчасовые отметки, точное размещение встреч без округления, линия текущего времени с обновлением раз в секунду. Первоначальное центрирование сохраняет дальнейшую ручную прокрутку.
- Загрузка, пустое расписание, ошибки, блокировка повторных операций, мобильная компоновка и переключение темы.

Начальная дата — сегодня; демонстрационная встреча занимает 12:00–13:00. После окончания рабочего дня выберите будущую дату. Дата и время встречи локальные для браузера; API использует `YYYY-MM-DD` и `HH:mm`. Общий форматтер календарной даты использует UTC только для отображения выбранного дня без сдвига между часовыми поясами.

Чтобы проверить 409, раскройте «Проверить серверный конфликт», нажмите «Смоделировать конфликт» и создайте встречу в свободном будущем интервале. Mock API добавит конкурирующую встречу; введённые поля останутся в форме.

## Архитектура

| Модуль                                      | Ответственность                                                                                                      |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `app/providers`                             | DI и единственный глобальный `ScheduleProvider` над роутером                                                         |
| `entities/meeting`, `entities/day-schedule` | DTO, сервисы, правила встреч, неизменяемое расписание и проекция на 1440 минутных слотов                             |
| `widgets/day-schedule/model`                | Машина расписания, контекст, селекторы и `useScheduleData`; подтверждённые и оптимистические данные, commit/rollback |
| `features/meeting-editor`                   | Дочерняя машина редактора, валидация черновика и форма                                                               |
| `features/delete-meeting`                   | Управляющий компонент с контекстом и отдельный диалог с props                                                        |
| `widgets/day-schedule/ui`                   | `DayScheduleView`, `EditableDaySchedule`, общая сетка с props, временные отметки и статусы                           |
| `widgets/meeting-management`                | Получение данных и отправка событий выбора даты, изменения черновика, сохранения и отмены                            |
| `pages/display`                             | Отдельная машина и `DoorSchedule` с автообновлением; использует общую сетку без действий                             |
| `shared/lib`                                | Форматирование дат/времени, DOM-хук центрирования и чистая геометрия прокрутки                                       |
| `app/mocks`, `shared/api`                   | MSW-хранилище, повторная серверная валидация, HTTP-клиент и типизированные ошибки                                    |

Страницы собирают компоненты; управляющие компоненты используют хуки и отправляют события. Общая сетка не читает машины. Селекторы сосредоточены в `model`, данные расписания читаются через `useScheduleData`. QueryStore шаблона не владеет бронированиями.

`meetingEditor` вызывается на корневом уровне машины расписания: обновление списка не пересоздаёт редактор и не стирает поля. Устаревшие ответы другой даты игнорируются XState. Программная установка и восстановление фокуса удалены по согласованному решению; стандартное поведение браузера сохранено.

### Чистые функции

| Файл                                                           | Вычисления без React и DOM                                                |
| -------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `widgets/meeting-management/model/meeting-management-view.ts`  | Видимость форм, блокировка создания, уведомление и подпись даты           |
| `widgets/day-schedule/model/grid-layout.ts`                    | Геометрия сетки, группировка встреч по строкам и временные отметки        |
| `widgets/day-schedule/model/meeting-presentation.ts`           | Название, статус, время и доступность действий карточки                   |
| `features/meeting-editor/model/editor.logic.ts`                | Начальный черновик, валидация и построение событий редактора              |
| `widgets/day-schedule/model/schedule.logic.ts`                 | Преобразования контекста, оптимистические операции, commit/rollback       |
| `shared/lib/date-time.ts`, `shared/lib/dom/scroll-geometry.ts` | Календарная дата, минуты, центрирование и компенсация отступов при resize |

API: GET `/api/bookings?date=…`, POST `/api/bookings`, PATCH/DELETE `/api/bookings/:id`. Ошибки: 400 — валидация, 404 — отсутствующая встреча, 409 — пересечение. DELETE возвращает 204 без JSON.

## Проверки

Перед первым запуском браузерных тестов установите Chromium:

```sh
bunx playwright install chromium
```

```sh
bun run check
bun run build
bun run test:e2e
bun run test:ct
```

`check` запускает TypeScript, oxlint, oxfmt и unit-тесты из `src`. E2E и компонентные тесты выполняются отдельно. Проверено 29.10.2026: **125 unit-тестов, 19 E2E и 2 компонентных теста**. Unit-тесты проверяют границы времени, чистые преобразования, неизменяемость входов и геометрию; E2E — реальное взаимодействие с browser MSW, CRUD, 409, ошибки обновления, навигацию и оба режима сетки. Stately проверяется через тестовый receiver; доступность внешнего сайта не является условием тестов.

Историческая симуляция из `docs` не входит в код приложения и общий `check`:

```sh
bun test ./docs/day-schedule.logic.test.js
```

Её 82 теста проверены отдельно. Дополнительно проверен production preview: загрузка worker, создание/изменение/удаление встречи, 409 с сохранением черновика и прямое открытие `/display`, без ошибок JavaScript. Это не подтверждает работу публичного deployment.

В dev-режиме доступны локальный XState Inspector и кнопка открытия Stately Inspector. На `/display` локальная панель скрыта, из production оба инспектора исключаются.

## Что осталось и ограничения

Проверка реализации по PRD не выявила незавершённых веток основных локальных сценариев; результаты ограничены перечисленными автоматическими проверками.

- в идеале продолжить рефакторинг кода и улучшить компонентную архитектуру
- перевести архитектуру в полноценную слотовую архитектуру FSD
- реализовать более простое подключение через DI для функционала запросов сервиса.
